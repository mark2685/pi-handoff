The presentation layer renders handoff gates, widgets, the read-only text viewer, and model choices. It follows `domain <- app <- adapters <- index.ts`; external effects remain behind ports and adapters.

Each surface is split in two: a pure formatter that owns what is said (and is unit-tested), and a thin `ctx.ui.custom` shell that only renders lines and resolves a stable menu id, because overlay key handling is not practically testable and should hold no decisions. Gate A places the optional draft BLUF and definition of done above a row-budgeted prompt preview, labels an in-memory leftovers follow-up, and moves Cancel first when that follow-up has no definition of done. Gate B parses the review's `Leftovers:` block to omit the no-work follow-up action and keeps that action after the viewers; its report, diffstat, review, and crash-tail previews share the rows left after fixed content, retaining a three-rendered-row floor and signpost. The thin Gate A and Gate B wrappers pass `tui.terminal.rows` to their formatters, while omitted rows retain the historical twelve, twenty-four, twelve, and eight-line caps for non-TUI callers. The running widget truncates to its Text content width, shows two conditions in a 24-row terminal, and expands to at most five on taller terminals while retaining metrics and the abort hint.

The text viewer follows the same split, with two exceptions worth knowing before editing it. Its windowing is measured in rendered rows rather than source lines and therefore runs inside `render(width)`, where the real width is known — the wrapped paragraphs it exists to display occupy several rows each, and a window counted in source lines overflows the terminal. Paging is part of that: `windowLines` returns the offsets one page forward and back alongside the window, and the component navigates by the window it last rendered, because a page expressed in rows and applied as a line offset skips whatever falls between two screens. And the text viewer and running widget match Escape through pi-tui's `matchesKey`, not by comparing raw bytes, because the Kitty keyboard protocol delivers plain Escape as `\x1b[27u`; `closesViewer` and `isAbortKey` are exported so those decisions stay testable.
