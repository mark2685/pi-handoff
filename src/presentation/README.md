The presentation layer renders the three gates (`launch-gate.ts`, `result-gate.ts`, `questions-gate.ts`), the run monitor, the read-only text viewer, and model choices, in the vocabulary of the root `CONTEXT.md`. It follows `domain <- app <- adapters <- index.ts`; external effects remain behind ports and adapters.

Each gate is split in two: a pure content builder that owns what is said (`launchGateContent`, `resultGateContent`, `questionsGateContent`; unit-tested), and the shared **gate frame** (`gate-frame.ts`) that owns how much of it fits. A gate module builds a `GateSpec` — title, fixed header lines, menu, evidence blocks in priority order, hint — and `openGate` renders it with `ctx.ui.custom`; the gate module makes no height decisions. The frame fits in rendered rows inside `render(width)`, exactly as the text viewer does, lays out title, header, menu, evidence, hint, shrinks blocks in priority order to a two-row-plus-signpost floor, hides what cannot reach the floor behind a hidden-blocks line, cuts the header from the bottom last, and never cuts the menu (design §5.10, ADR-0001). The budget is `tui.terminal.rows` less `DOCK_RESERVED_ROWS` for the fullscreen dock's other occupants. The result gate's `resolveMenu` receives the blocks a fit shortened — at construction and again after any resize that changes the set — and drops the viewer for any block shown in full; blocks name their viewer by option id and the signpost takes its label from the menu offered, so it cannot name an option the gate does not render — **View full report**, **View partial output**, and **View full diffstat** (which appends the stderr tail) are offered exactly when their text is hidden — because a read-only viewer with nowhere to navigate is a broken promise. `formatLaunchGateSummary`, `formatResultGateSummary`, and `formatQuestionsGateSummary` return the untruncated content for callers and tests without a terminal. The launch gate places the goal and definition of done in the header above the menu and the prompt below it as the one block; the result gate puts the reviewer's verdict with the identity lines at the top of the header, above the menu it orders and out of reach of a bottom-up header cut, with report, findings, diffstat, partial output, and stderr tail below in that priority. The discard summary (`discardSummarySpec`) is a gate too: the skipped-path warning is its header and the path lists its one block, with **View all paths** offered exactly when a list was cut. The run monitor is not a gate and keeps its own 24-row budget: it gives the current Pi phase, active tools, and the time since the last worker event; a pulse means only the surface is still rendering, so silence remains explicit. It truncates to its content width, shows two conditions in a 24-row terminal, and expands to at most five on taller terminals while retaining metrics and the abort hint.

The drafting loader follows the same split too: `formatDraftingLoaderMessage` is pure and formats its action text, elapsed time, and the reviewing-session drafting model when available, while its shell owns the cancellable loader signal and a one-second message refresh. The stock `BorderedLoader` has no public message updater, so the shell uses an equivalent bordered `CancellableLoader` composition rather than reaching through its private child; cancellation remains signal-driven.

The text viewer follows the same split, with two exceptions worth knowing before editing it. Its windowing is measured in rendered rows rather than source lines and therefore runs inside `render(width)`, where the real width is known — the wrapped paragraphs it exists to display occupy several rows each, and a window counted in source lines overflows the terminal. Paging is part of that: `windowLines` returns the offsets one page forward and back alongside the window, and the component navigates by the window it last rendered, because a page expressed in rows and applied as a line offset skips whatever falls between two screens. And the text viewer and run monitor match Escape through pi-tui's `matchesKey`, not by comparing raw bytes, because the Kitty keyboard protocol delivers plain Escape as `\x1b[27u`; `closesViewer` and `isAbortKey` are exported so those decisions stay testable.
