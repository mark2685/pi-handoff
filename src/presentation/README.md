The presentation layer renders handoff gates, widgets, the read-only text viewer, and model choices. It follows `domain <- app <- adapters <- index.ts`; external effects remain behind ports and adapters.

Each surface is split in two: a pure formatter that owns what is said (and is unit-tested), and a thin `ctx.ui.custom` shell that only renders lines and resolves a stable menu id, because overlay key handling is not practically testable and should hold no decisions.

The text viewer follows the same split, with two exceptions worth knowing before editing it. Its windowing is measured in rendered rows rather than source lines and therefore runs inside `render(width)`, where the real width is known — the wrapped paragraphs it exists to display occupy several rows each, and a window counted in source lines overflows the terminal. Paging is part of that: `windowLines` returns the offsets one page forward and back alongside the window, and the component navigates by the window it last rendered, because a page expressed in rows and applied as a line offset skips whatever falls between two screens. And its key decisions are matched with pi-tui's `matchesKey`, not by comparing raw bytes, because the Kitty keyboard protocol delivers plain Escape as `\x1b[27u`; `closesViewer` is exported so that one decision stays testable.
