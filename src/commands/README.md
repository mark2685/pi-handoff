The commands layer parses `/handoff [--model provider/model-id[:thinking]] [scope]` arguments and dispatches application behavior. A leading `--model` is resolved against the live registry before drafting; later prose mentions remain scope text. It follows `domain <- app <- adapters <- index.ts` and does not construct adapters.

The drafting loop in `handoff-command.ts` serves two sources — `/handoff` and Gate B's "Accept and hand off leftovers" — and the difference between them holds for every pass of the loop, not just the first. A leftovers draft carries its scope (the accepted prompt plus the parsed `Leftovers:` items, or full legacy review text only when the block is missing) from the first call onwards and re-enters through `DraftService.draftLeftovers` on a retry and on a re-draft after answered questions, so the transcript is never read on that path. A `no_leftovers` outcome notifies and returns without Gate A. Changing either continuation branch to call `draft` would silently reintroduce the conversation _and_ drop the leftovers documents out of the scope; `test/commands/handoff-command.test.ts` asserts zero transcript reads across both branches.
