The commands layer will parse `/handoff` arguments and dispatch application behavior. It follows `domain <- app <- adapters <- index.ts` and does not construct adapters.

The drafting loop in `handoff-command.ts` serves two sources — `/handoff` and Gate B's "Accept and hand off leftovers" — and the difference between them holds for every pass of the loop, not just the first. A leftovers draft carries its scope (the accepted prompt plus the review text) from the first call onwards and re-enters through `DraftService.draftLeftovers` on a retry and on a re-draft after answered questions, so the transcript is never read on that path. Changing either continuation branch to call `draft` would silently reintroduce the conversation _and_ drop the leftovers documents out of the scope; `test/commands/handoff-command.test.ts` asserts zero transcript reads across both branches.
